# 개선 계획 (2026-11-05) — 효과 큰 순서

| 순위 | 항목 | 기대 효과 | 구현 |
|---|---|---|---|
| 1 | **enforce**: 반복 확인된 교훈을 훅으로 강제 | 교훈은 '권고'라 모델이 무시할 수 있음. 공식 가이드: "강조를 반복하게 되면 그 줄은 훅에 들어가야 한다". 가장 자주 틀리는 것부터 결정론적으로 막음 | `cli.py enforce list/emit/apply`, `/self-tuner:enforce` 스킬. hookify 가 있으면 위임, 없으면 `type: prompt` 훅(LLM 평가형)을 `~/.claude/settings.json` 에 사용자 승인 후 추가. 강제된 교훈은 rules 뷰에서 제외(중복 방지) |
| 2 | **weekly**: 주간 유지보수 리포트 | 메모리 시스템의 고질병(비대화·stale)을 주 1회 15초로 해결. 사람이 안 들여다봐도 유지됨 | `cli.py weekly` + `/self-tuner:weekly` 스킬 + `~/.claude/loop.md` 샘플 + Desktop 예약 작업 안내 |
| 3 | **recommend**: ECC 포크에서 맞는 스킬만 추천 | ECC 314개 통째 설치는 설명만 ~100KB 상시 로드. 사용 기록 기반으로 5~10개만 골라 복사 → 컨텍스트 절약 + 실제 쓰는 스킬만 | `cli.py recommend --ecc-dir`, `mine` 리포트에 통합 |
| 4 | 예측 검증 agent 훅 | 교훈의 helpful/harmful 을 자동 채점 | 다음 라운드 |
| 5 | 임베딩 검색(model2vec) | 교훈 200개 이상일 때 검색 품질 | 다음 라운드(선택 의존성) |

판단 근거: 1·2는 self-tuner 가 없을 때 사용자가 겪는 비용(같은 말 반복, 메모리 썩음)을 직접 줄인다. 3은 외부 자산(ECC)의 가치를 비용 없이 끌어온다. 4·5는 데이터가 쌓인 뒤에야 효과가 난다.
